# 指标查询用户身份与数据范围适配设计

## 目标

- `userId` 只表示方案、收藏、个人指标的创建人或修改人，不参与指标数据权限计算。
- 本地用户按 `sys_user.guoku_id` 对应国库及全部下级国库查询。
- 门户 OAuth 用户按令牌中的 `subject_code` 对应 `dmcode.cm_guoku_dimnsn.bookorgcode`，查询该所属国库及全部下级国库。
- 保存方案 SQL 不固化创建人或所属国库；每次执行时按当前查看人动态叠加数据范围。

## 实现边界

1. `org-tribe-system` 在完成 Shiro 鉴权后覆盖并注入内部请求头：当前用户 ID、门户 `subject_code` 或本地 `guoku_id`。外部同名请求头不可信，必须由网关重写。
2. `indicatorsLib` 只消费网关注入的上下文。创建人字段统一由服务端覆盖，忽略前端传入的用户 ID。
3. `CreateSchemeSQL` 只生成与用户无关的基础 SQL。查询、图表、导出和已保存方案执行前，再用当前上下文包装国库范围。
4. 门户 `subject_code` 或本地 `guoku_id` 无法映射时失败关闭，不回退到全量数据。
5. 历史 MySQL/Vastbase 保存 SQL 中固化的用户权限子句由迁移脚本移除，保留字段大写双引号适配结果。

## 数据范围

- 维度 `1`：授权集合返回 `guoku_id`。
- 维度 `2`：授权集合返回 `area_no_id`。
- 门户根节点：`bookorgcode = subject_code`；本地根节点：`guoku_id = guoku_id`。
- 使用递归国库树获取根节点及全部后代，并与页面显式选择的 `dimCode` 取交集。

## 兼容性

- 前端暂时继续发送 `userId` 不影响结果，但后端不再信任它。
- 本地登录与门户 OAuth 共用同一指标执行路径；只有国库根节点来源不同。
- 历史方案的创建人字段不改变，只有方案 SQL 内的数据范围被移除并改为运行时计算。
