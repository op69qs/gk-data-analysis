# 分析平台本地与门户顶部菜单排序一致性设计

## 背景

分析平台顶部菜单受容器宽度限制，超出可见区域的一级菜单会收纳到右侧“…”入口。当前“系统管理”排在前面，“可视化大屏”排在最后，因此在当前分辨率下可视化入口被收纳。

目标是让业务菜单优先展示：“可视化大屏”显示在顶部，“系统管理”排到最后并在宽度不足时进入“…”。本地 JEECG 菜单与门户 `GK_DATA_ANALYSIS` 权限定义保持一致。

## 目标顺序

1. 首页
2. 智能报告
3. 指标库
4. 综合查询
5. 数据报表
6. 数据处理
7. 可视化大屏
8. 系统管理

当顶部宽度不足时，排在最后的“系统管理”优先进入“…”。

## 实现方案

仅调整菜单元数据排序，不修改 Vue 顶部菜单组件、路由生成逻辑或溢出算法。

- 分析平台本地库 `"jeecg-boot-os".sys_permission`：
  - `vis_root_menu_20260423` 的 `sort_no` 设为 `23`。
  - `d7d6e2e4e2934f2c9385a623fd98c6f3` 的 `sort_no` 设为 `9999`。
- 门户库 `gk_nexus.subsystem_permission`：
  - `sys_code='GK_DATA_ANALYSIS'` 且 `permission_code='vis_root_menu_20260423'` 的 `sort_order` 设为 `23`。
  - `sys_code='GK_DATA_ANALYSIS'` 且 `permission_code='d7d6e2e4e2934f2c9385a623fd98c6f3'` 的 `sort_order` 设为 `9999`。
- 同步修改本地和门户的权限初始化 SQL，避免重刷后恢复旧顺序。

`23` 位于“数据处理”当前排序 `22` 之后；`9999` 用于明确表达“系统管理最后”，避免依赖同序号下不稳定的 ID 比较。

## 边界与非目标

- 不隐藏或删除“系统管理”，仅调整它的顶部顺序。
- 不改变任何角色、用户权限和父子菜单关系。
- 不强制固定“…”中的菜单数量；实际收纳数量仍由浏览器宽度和 Ant Design Vue 水平菜单决定。
- 不调整二级菜单顺序。

## 验证

1. 回查本地与门户两张权限表，确认可视化大屏为 `23`、系统管理为 `9999`。
2. 确认两个菜单的启用状态、父节点、路由和角色授权没有变化。
3. 本地 `admin` 重新登录或强制刷新后，可视化大屏出现在顶部，系统管理位于末尾并在宽度不足时进入“…”。
4. 通过门户 OAuth 登录后重复同样验证，确认顺序与本地登录一致。

## 回滚

如需回滚，将本地和门户的系统管理排序恢复为 `2`，可视化大屏排序恢复为 `999`。
