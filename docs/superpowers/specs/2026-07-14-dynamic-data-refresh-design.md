# 动态刷数页面恢复设计

## 背景

数据分析平台的“动态刷数”菜单目前打开后没有业务内容。现有源码只保留了错误日志查询功能，而需求目录中的生产 `org-tribe-system-2.1.0.jar` 包含动态刷数的前端页面、接口和执行逻辑。本次以生产 JAR 的业务行为和生产截图为基准，在当前 Vue 2、Spring Boot、MyBatis 和 Vastbase/PostgreSQL 技术栈上恢复功能。

## 目标

- 恢复动态刷数任务列表及查询条件。
- 支持新增、修改、启动和删除任务。
- 支持存储过程任务和服务器脚本任务。
- 保持生产 JAR 的接口路径、字段名称、任务类型和状态含义。
- 为当前 Vastbase 环境提供临时的 `adm.exec_shell_task` 建表脚本。
- 修复生产 JAR 中会造成误报成功、误删、命令拼接错误或注入风险的明显缺陷，但不改变用户可见流程。

## 不在本次范围内

- 不新增任务调度、Cron 管理或定时执行界面。
- 不改造现有菜单权限和动态路由机制。
- 不迁移生产 MySQL 历史数据。
- 不保证临时 DDL 与尚未提供的生产 MySQL DDL 在字段长度、默认值和索引上完全一致；后续取得生产 DDL 后单独核对修订。

## 证据基线

生产 JAR 和截图确认了以下行为：

- 页面组件路径为 `manualCallReport/manualCallReportList`，源码组件名为 `manualCallReportList`。
- 列表字段为任务名称、类型、执行状态、脚本路径、脚本名称、参数和操作。
- 查询条件为任务名称和执行状态。
- 操作为修改、启动、删除，并具有启动和删除确认提示。
- 表单字段为 `task_name`、`task_type`、`shell_path`、`shell_name`、`shell_param`。
- 接口前缀为 `/errorLogController`，接口包括 `getData`、`add`、`edit`、`callProc`、`del`。
- 任务类型：`1` 为存储过程，`2` 为 shell 脚本。
- 状态：`0` 未执行、`1` 正在执行、`200` 成功、`500` 失败。
- 启动操作先写入状态 `1`，再在后台线程执行。
- 存储过程接收业务参数和任务 ID 两个参数。
- shell 脚本按进程退出码写入 `200` 或 `500`。

## 总体结构

沿用现有分层，不新增平行模块：

1. `org-tribe-view` 恢复动态刷数列表和编辑弹窗。
2. 前端 API 继续通过现有请求工具访问 `/errorLogController/*`。
3. `ErrorLogController` 提供列表、CRUD 和启动接口。
4. `ErrorLogService` 负责任务读取、数据变更和异步执行协调。
5. `ErrorLogMapper` 访问 Vastbase 的 `adm.exec_shell_task`，并调用动态存储过程。
6. 后台执行器根据 `task_type` 选择存储过程或服务器脚本。

## 前端设计

### 列表页面

恢复 `src/views/manualCallReport/manualCallReportList.vue`：

- 查询区包含任务名称、执行状态、查询、新增和重置。
- 状态下拉包含未执行 `0`、执行成功 `200`、执行失败 `500`；正在执行状态仍可在列表中显示，但不作为生产截图中的筛选项新增。
- 表格按生产截图显示七个业务列和操作列。
- 类型显示为“存储过程”或“shell脚本”。
- 状态显示为“未执行”“正在执行”“成功”“失败”。
- 启动和删除使用二次确认。
- 正在执行的任务不允许重复启动或删除。
- 所有请求期间保留加载状态，成功后重新加载列表。

### 编辑弹窗

恢复 `src/views/manualCallReport/modules/callModal.vue`：

- 新增和修改共用一个弹窗。
- 五个业务字段均必填。
- 类型可选存储过程和 shell 脚本。
- 参数不沿用旧 JAR 中不合理的 4 到 10 字符限制，改为必填且最多 1000 字符，以支持日期区间及其他过程参数。
- 修改时回填原记录；提交时根据是否存在 ID 调用新增或修改接口。

### API

在现有 API 模块中恢复以下封装：

- `POST /errorLogController/getData`
- `POST /errorLogController/add`
- `POST /errorLogController/edit`
- `POST /errorLogController/callProc`
- `POST /errorLogController/del`

接口响应继续兼容现有页面使用的 `result`、`msg`、`rows` 和 `total` 格式。

## 后端设计

### 查询

- `task_name` 使用参数化的模糊匹配。
- `status` 使用精确匹配。
- 结果按创建时间倒序，保持最新任务优先。
- 返回总数和当前页数据，使用当前项目既有 `pageNo`、`pageSize` 约定。

### 新增

- 服务端生成 32 位 ID。
- 初始状态固定为 `0`。
- 服务端写入创建时间。
- 只接受五个业务字段，忽略客户端提交的 ID、状态和审计字段。

### 修改

- 只允许更新五个业务字段和更新时间。
- 不允许通过普通修改接口改变执行状态。
- 运行中任务不允许修改。
- 记录不存在时返回失败。

### 启动

- 启动接口只使用客户端传入的任务 ID。
- 服务端按 ID 重新读取完整任务，避免信任客户端传来的脚本路径、过程名、任务类型或状态。
- 任务不存在或状态为 `1` 时拒绝启动。
- 状态以条件更新方式从当前状态改为 `1`，防止并发重复启动。
- 后台执行提交成功后立即返回“正在调用中，请稍后查看”。
- 后台执行完成后刷新更新时间，并写入 `200` 或 `500`。

### 存储过程执行

- `task_type=1` 时执行 `shell_name` 指定的过程。
- 过程名只允许小写或大小写字母、数字、下划线组成的 `schema.procedure` 格式；Vastbase 未加引号的标识符最终按小写解析。
- 过程参数和任务 ID 使用绑定参数，不拼接用户值。
- 动态过程名无法使用 JDBC 占位符，因此仅在格式校验通过后插入语句。
- 调用形态保持生产 JAR 语义：`call schema.procedure(shell_param, id)`。
- 过程可自行更新任务状态；若过程正常返回但未更新状态，执行器补写 `200`。异常统一补写 `500`。

### shell 脚本执行

- `task_type=2` 时使用 `shell_path` 与 `shell_name` 组合出可执行文件路径。
- 修复生产 JAR 忽略 `shell_name` 的历史缺陷。
- 不通过 `/bin/sh -c` 解释字符串，避免 shell 元字符注入。
- 使用参数列表启动进程；`shell_param` 整体作为一个进程参数传入，不按空格拆分，也不重复传入去除连字符后的副本。
- 可执行文件必须位于配置允许的目录中，规范化路径后不得逃逸允许目录。
- 退出码 `0` 写入 `200`，其他退出码或异常写入 `500`。
- 服务端日志记录任务 ID、执行类型、耗时、退出码和错误摘要，不记录数据库密码等敏感配置。

### 删除

- 只按 ID 删除，修复生产 JAR 中 `id = ? or shell_name = ?` 可能误删同名任务的问题。
- 运行中任务禁止删除。
- 记录不存在时返回失败。

### 错误响应

- Controller 捕获异常后返回真实失败，不再复刻生产 JAR 中异常后覆盖成成功响应的问题。
- 用户消息保持简洁，详细堆栈进入服务端日志。
- 后台任务异常必须尽力将状态从 `1` 更新为 `500`。

## 临时 Vastbase 表设计

临时迁移脚本创建 `adm.exec_shell_task`。所有 schema、表名和字段名使用未加双引号的小写标识符，符合 Vastbase/PostgreSQL 默认折叠规则。

根据生产 JAR 的 INSERT 顺序暂定以下字段：

| 字段 | 临时类型 | 约束/用途 |
| --- | --- | --- |
| `id` | `varchar(32)` | 主键 |
| `task_name` | `varchar(200)` | 非空，任务名称 |
| `shell_path` | `varchar(500)` | 非空，脚本目录或存储过程辅助路径 |
| `shell_name` | `varchar(300)` | 非空，脚本名或过程名 |
| `shell_param` | `varchar(1000)` | 非空，执行参数 |
| `cron_id` | `varchar(32)` | 兼容 JAR，暂不使用 |
| `status` | `varchar(3)` | 非空，默认 `0` |
| `create_time` | `timestamp without time zone` | 非空，默认当前时间 |
| `create_user` | `varchar(32)` | 可空 |
| `update_time` | `timestamp without time zone` | 可空 |
| `update_user` | `varchar(32)` | 可空 |
| `task_type` | `varchar(1)` | 非空，限制为 `1` 或 `2` |

同时创建 `status` 索引和 `task_name` 索引。迁移文件明确标注为临时推断版本；取得生产 MySQL DDL 后比较字段长度、空值约束、默认值、索引和注释，再提供兼容迁移。

## 安全边界

- 列表、CRUD 和启动接口继续受项目现有登录及权限体系保护。
- 所有普通 SQL 值使用绑定参数。
- 动态过程名执行前进行严格格式校验。
- shell 可执行路径必须落在配置允许目录内。
- 不接受前端直接提交的任意命令字符串。
- 运行中状态使用条件更新，避免重复执行。

## 测试与验收

### 后端自动化测试

- 查询条件和分页参数正确传递。
- 新增任务生成 ID、状态 `0` 和创建时间。
- 修改只更新允许字段。
- 异常时接口返回失败，不被成功结果覆盖。
- 删除只按 ID，运行中任务拒绝删除。
- 同一任务并发启动时只有一次状态切换成功。
- 存储过程名非法时拒绝执行。
- shell 路径逃逸允许目录时拒绝执行。
- shell 退出码正确映射到 `200` 和 `500`。
- 后台异常将运行中状态恢复为 `500`。

### 前端自动化或组件级验证

- 列表字段、类型和状态文案正确。
- 查询、重置、新增、修改、启动和删除调用正确接口。
- 表单必填校验和编辑回填正确。
- 运行中任务不能重复启动或删除。

### 构建与浏览器验收

- 后端测试及编译通过。
- Vue 2 前端 lint/build 通过。
- 在真实浏览器中验证页面可打开且不再为空。
- 对照生产截图验证布局、筛选项、表格、弹窗和确认提示。
- 在 Vastbase 测试库验证临时 DDL、CRUD、筛选和状态流转。
- 分别用一个测试过程和一个测试脚本验证两类执行路径。
