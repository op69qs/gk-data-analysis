# 现场 Eureka、Nacos 配置修改步骤

## 一、Eureka 服务端（8761、8762）

以下按附件目录 `/opt/app/guoku/dwbi-er` 操作。附件 JAR 已包含认证依赖，使用 `security.user` 配置；不要写成 `spring.security.user`，不用替换 JAR。

### 1. 备份

使用原来启动 Java 的系统账号执行：

```bash
cd /opt/app/guoku/dwbi-er
backup_dir="backup-eureka-$(date +%Y%m%d%H%M%S)"
mkdir -p "$backup_dir"
cp -p dwbi-eureka.jar start_jar.sh stop_jar.sh "$backup_dir/"
ss -lntp | grep -E ':(8761|8762)[[:space:]]'
```

附件脚本只启动 8761。根据上面 PID 核对 8762 的实际启动目录和 JAR；8762 使用相同启动包时，按下面 `peer2` 启动。如果是其他包，先核对该包，不能只修改 8761 就算两个端口完成。

### 2. 创建外部认证配置

只执行一次生成密码，两个端口共用此文件：

```bash
cd /opt/app/guoku/dwbi-er
umask 077
mkdir -p config logs
if [ -e config/eureka-security.properties ]; then
  cp -p config/eureka-security.properties "$backup_dir/"
fi
cat > config/eureka-security.properties <<'EOF'
security.basic.enabled=true
security.basic.path=/**
security.enable-csrf=false
security.user.name=eureka_service
management.security.enabled=true
eureka.client.register-with-eureka=false
eureka.client.fetch-registry=false
eureka.client.serviceUrl.defaultZone=http://${security.user.name}:${security.user.password}@127.0.0.1:${server.port}/eureka/
EOF
printf 'security.user.password=%s\n' "$(openssl rand -hex 24)" >> config/eureka-security.properties
chmod 600 config/eureka-security.properties
```

用户名为 `eureka_service`。从文件中的 `security.user.password` 读取新密码，供下面所有 Eureka 客户端使用。不要继续使用 JAR 内置旧密码。

### 3. 替换 start_jar.sh

将 `/opt/app/guoku/dwbi-er/start_jar.sh` 全部替换为：

```bash
#!/bin/bash
set -euo pipefail
APP=/opt/app/guoku/dwbi-er
cd "$APP"
PROFILE="${1:-peer1}"
case "$PROFILE" in
  peer1) PORT=8761 ;;
  peer2) PORT=8762 ;;
  *) echo "用法: bash start_jar.sh peer1|peer2"; exit 1 ;;
esac
if ss -lntH "sport = :$PORT" | grep -q .; then
  echo "$PORT 已被占用，请先核对并停止旧 Eureka 进程"
  exit 1
fi
test -r "$APP/config/eureka-security.properties"
mkdir -p "$APP/logs"
nohup java -Xms128m -Xmx128m \
  -jar "$APP/dwbi-eureka.jar" \
  --spring.profiles.active="$PROFILE" \
  --server.port="$PORT" \
  --spring.config.location="file:$APP/config/eureka-security.properties" \
  > "$APP/logs/eureka-$PROFILE.log" 2>&1 < /dev/null &
echo "$PROFILE 已发起启动，PID=$!，日志=$APP/logs/eureka-$PROFILE.log"
```

### 4. 替换 stop_jar.sh

将 `/opt/app/guoku/dwbi-er/stop_jar.sh` 全部替换为以下内容，避免原脚本同时杀掉 portal、register：

```bash
#!/bin/bash
set -euo pipefail
PIDS=$(pgrep -f 'java .* -jar /opt/app/guoku/dwbi-er/dwbi-eureka.jar([[:space:]]|$)' || true)
if [ -z "$PIDS" ]; then
  echo "未找到本目录 Eureka 进程"
  exit 0
fi
kill $PIDS
for ((i=0; i<30; i++)); do
  running=false
  for pid in $PIDS; do
    if kill -0 "$pid" 2>/dev/null; then running=true; fi
  done
  if [ "$running" = false ]; then echo "Eureka 已停止"; exit 0; fi
  sleep 1
done
echo "Eureka 尚未退出，检查进程后再启动"
exit 1
```

### 5. 维护窗口切换

先准备第二节的全部客户端配置，再一起切换服务端和客户端：

```bash
cd /opt/app/guoku/dwbi-er
bash -n start_jar.sh
bash -n stop_jar.sh
bash stop_jar.sh
bash start_jar.sh peer1
# 仅在确认 8762 同样使用此包、且原 8762 进程已停止后执行：
bash start_jar.sh peer2
```

检查两个启动日志出现 `Started EurekaServerApplication`，且 `ss -lntp` 显示对应监听。不要再执行旧的停止脚本。

## 二、Eureka 客户端（数据分析、ER 等业务服务）

### 1. 找到实际加载的配置

在每个业务工程的现场部署根目录执行：

```bash
grep -rlE 'defaultZone|EUREKA_DEFAULT_ZONE' config --include='*.yml' --include='*.yaml' --include='*.properties'
```

修改实际生效的 `application-dev.yml`、`application.yml` 或 `bootstrap.yml`。启动参数/环境变量中的 `EUREKA_DEFAULT_ZONE` 如有设置，也必须同步修改。

### 2. 替换注册地址

将原 `eureka.client.serviceUrl.defaultZone` 改为以下内容，`替换为新密码` 使用服务端配置文件中的同一个密码：

```yaml
eureka:
  client:
    serviceUrl:
      defaultZone: "http://eureka_service:替换为新密码@11.8.168.69:8761/eureka/,http://eureka_service:替换为新密码@11.8.168.69:8762/eureka/"
```

只有 8761 实际运行时，仅保留第一个地址。原文件使用 `service-url` 时沿用原字段名称；修改原值，不重复添加第二个 `eureka` 配置块。保留客户端原有 `register-with-eureka`、`fetch-registry` 设置。

以下模块只要指向这两个端口，就全部修改并按原脚本重启：

- 数据分析：主系统、SEO、指标库、报表、统计分析、系统对接、可视化等已启用 Eureka 的模块。
- ER：portal、register。
- 其他使用该注册中心的业务服务。

### 3. 验证

不带密码应返回 `401`：

```bash
for port in 8761 8762; do
  curl --max-time 10 -sS -o /dev/null -w "$port anonymous: %{http_code}\n" "http://11.8.168.69:$port/eureka/apps"
done
```

带账号执行，按提示输入新密码，应返回 `200`：

```bash
curl --max-time 10 -u eureka_service -sS -o /dev/null -w '%{http_code}\n' http://11.8.168.69:8761/eureka/apps
curl --max-time 10 -u eureka_service -sS -o /dev/null -w '%{http_code}\n' http://11.8.168.69:8762/eureka/apps
```

浏览器访问两个 Eureka 首页应要求认证。业务服务重启后，在控制台核对实例为 `UP`，观察至少两个客户端心跳周期，确认无持续 `401/403`、注册失败或续约失败。

## 三、Nacos 服务端（8848）

### 1. 进入现场 Nacos 安装目录并确认版本

附件没有 Nacos 包。下列步骤适用于 Nacos 1.4.1～2.x；先将路径改为现场实际安装目录：

```bash
cd /实际安装路径/nacos
unzip -l target/nacos-server.jar | grep -E 'nacos-(core|auth|config|naming)-[0-9]' | head -c 2000
backup_dir="backup-auth-$(date +%Y%m%d%H%M%S)"
mkdir -p "$backup_dir"
cp -p conf/application.properties "$backup_dir/"
```

确认版本后，按第 3 步选对 Token 属性名。1.4.0 及更早版本、3.x 不套用下面配置。

### 2. 先准备客户端账号

登录 `http://11.8.168.69:8848/nacos/`：

1. 修改默认管理员账号密码。
2. 在权限管理中创建业务账号 `nacos_service`，设置独立强密码。
3. 为该账号建立业务角色，授予业务实际使用 namespace 的注册/发现、配置读取等所需权限；不授予管理员角色。
4. 按第四节将账号密码写入全部客户端配置，在维护窗口协调重启。

### 3. 生成密钥并修改 application.properties

先生成一次，集群全部节点使用同一组值：

```bash
umask 077
printf 'X-Nacos-%s\n' "$(openssl rand -hex 16)" > nacos-identity-key.txt
openssl rand -hex 32 > nacos-identity-value.txt
openssl rand -base64 32 > nacos-token-secret.txt
```

编辑 `conf/application.properties`，找到同名配置直接替换；没有的再追加。保留数据库、端口、集群等其余配置：

```properties
nacos.core.auth.system.type=nacos
nacos.core.auth.enabled=true
nacos.core.auth.enable.userAgentAuthWhite=false
nacos.core.auth.server.identity.key=填入nacos-identity-key.txt内容
nacos.core.auth.server.identity.value=填入nacos-identity-value.txt内容
```

**Nacos 2.1.x、2.2.x 及后续 2.x**，Token 配置为：

```properties
nacos.core.auth.plugin.nacos.token.secret.key=填入nacos-token-secret.txt内容
```

**Nacos 1.4.1～2.0.4**，Token 配置为：

```properties
nacos.core.auth.default.token.secret.key=填入nacos-token-secret.txt内容
```

集群所有节点的 identity key、identity value、Token 密钥必须完全一致。不要保留默认值，也不要给每台机器分别生成。配置可能动态生效，修改时就应进入维护窗口。

### 4. 重启

使用原启动账号执行。保持原单机/集群模式，以下两种启动命令只执行对应的一种：

```bash
bash bin/shutdown.sh
# 确认原进程退出后：
# 原来是单机：
bash bin/startup.sh -m standalone
# 原来是集群：
# bash bin/startup.sh -m cluster
```

集群逐台处理并检查节点状态，凭据切换期间允许业务维护中断。若现场由 systemd 或容器管理，则修改其持久化配置并通过原管理方式重启，不额外执行上面的脚本启动第二个实例。

## 四、Nacos 客户端

### 1. 修改每个客户端实际加载的配置

Nexus 的 `gk-auth`、`gk-system`、`gk-audit`、`gk-gateway`、`gk-bridge` 中，实际连接 `11.8.168.69:8848` 的模块均需修改。其他连接该 Nacos 的工程也同样处理。

在原有 `spring.cloud.nacos` 下合并以下内容，将 `替换为业务账号密码` 换成第三节创建的密码；保留原 namespace、group：

```yaml
spring:
  cloud:
    nacos:
      discovery:
        server-addr: 11.8.168.69:8848
        username: nacos_service
        password: "替换为业务账号密码"
      config:
        server-addr: 11.8.168.69:8848
        username: nacos_service
        password: "替换为业务账号密码"
```

仅使用服务注册、不使用配置中心的模块不加 `config` 段。通过 `bootstrap.yml` 拉取配置的模块，账号密码也写在 `bootstrap.yml` 或启动环境里。原配置使用环境变量时，更新对应变量；不要只修改一份不生效的 YAML。

直接使用 Nacos Java SDK 的程序，在创建 ConfigService/NamingService 的 Properties 中设置：

```java
properties.setProperty("username", "nacos_service");
properties.setProperty("password", nacosPassword); // 从部署配置读取
```

按原启停方式重启各客户端，确认服务实例健康、配置拉取成功。

### 2. 复测

以下三条请求都应被拒绝，不能返回用户列表：

```bash
curl --max-time 10 -sS -o /dev/null -w '%{http_code}\n' 'http://11.8.168.69:8848/nacos/v1/auth/users?pageNo=1&pageSize=1'
curl --max-time 10 -sS -o /dev/null -w '%{http_code}\n' -H 'serverIdentity: security' 'http://11.8.168.69:8848/nacos/v1/auth/users?pageNo=1&pageSize=1'
curl --max-time 10 -sS -o /dev/null -w '%{http_code}\n' -H 'User-Agent: Nacos-Server' 'http://11.8.168.69:8848/nacos/v1/auth/users?pageNo=1&pageSize=1'
```

若现场根路径也映射 Nacos，再将上述 `/nacos/v1/` 换成 `/v1/` 各测一次。返回 `200` 时检查是否是登录页面；只要仍返回用户数据，就未完成整改。

## 五、现场网络策略

在现有防火墙/安全组中配置源地址白名单：

| 目标端口 | 允许来源 |
|---|---|
| 8761、8762 | Eureka 业务客户端服务器、必要节点、运维主机 |
| 8848 | Nacos 业务客户端服务器、Nacos 节点、运维主机 |
| 9848（Nacos 2.x 默认客户端通信端口） | Nacos 业务客户端服务器、必要节点 |
| 9849、7848（Nacos 2.x 默认节点通信端口） | 仅 Nacos 节点 |

其他来源拒绝。端口经过自定义时使用实际监听端口。完成后重新扫描 8761、8762、8848。

参数对照：[Nacos 官方鉴权配置](https://nacos.io/en/docs/guide/user/auth/)。
