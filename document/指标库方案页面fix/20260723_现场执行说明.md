# 指标查询身份与数据范围现场执行说明

## 本次必须替换的服务

- `org-tribe-system-2.1.0.jar`：OAuth 缓存门户 `subject_code`，网关注入可信用户上下文。
- `indicatorsLib-2.1.0.jar`：保存 SQL 与用户解耦，查询时按当前用户所属国库树追加范围。
- `seo-2.1.0.jar`：VIS 推送指标方案按当前查看人追加同一范围，不再执行页面传入的指标 SQL。

三个服务必须作为同一批次上线，不能只替换其中一个。

## SQL 执行顺序

维护窗口停止上述服务后，只执行：

```sql
\i 20260723_apply_runtime_user_scope.sql
```

该脚本已包含：

1. 备份当前指标库和 VIS 保存 SQL；
2. 历史 MySQL SQL 转为 Vastbase；
3. 固定字段改为双引号大写别名；
4. 删除历史 SQL 中固化的创建人数据范围；
5. 校验指标库与 VIS SQL 一致，并逐条执行 `LIMIT 0`。

脚本成功提交后替换三个 JAR 并同时启动。若现场此前已经执行过 `20260722_migrate_saved_scheme_sql_to_vastbase.sql`，仍然只需执行本脚本；脚本可重复执行。

## 回滚

停止三个服务，恢复上一版三个 JAR，然后执行：

```sql
\i 20260723_apply_runtime_user_scope.rollback.sql
```

回滚脚本恢复本批次执行前的保存 SQL，不使用旧的 `20260722` 备份。
