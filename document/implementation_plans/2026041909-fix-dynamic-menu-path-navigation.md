# 修复动态菜单点击无响应

## 问题现象

- 前端左侧菜单中，综合查询下的维度表，以及数据报表下的分行业报表、企业报表、企业排名，点击后界面无反应。
- 后端日志、浏览器控制台都没有明显报错。

## 根因分析

- `org-tribe-view` 的左侧菜单来自后端 `sys_permission` 动态返回的数据。
- 菜单组件 `src/components/menu/index.js` 在渲染内部菜单时，默认使用 `router-link` 按 `menu.name` 导航。
- 这类动态菜单真正稳定的主键其实是 `path`，而不是 `name`：
  - `name` 可能为空。
  - `name` 可能重复。
  - `name` 可能与动态注入后的真实路由名不一致。
- 一旦 `name` 配置异常，Vue Router 会出现无效跳转或被当成重复跳转，当前项目又在 `router.push` 上吞掉了重复导航异常，所以最终表现为“点击没反应，也不报错”。

## 修改内容

- 将 `org-tribe-view/src/components/menu/index.js` 的动态菜单跳转方式统一改为按 `menu.path` 导航。
- 不再依赖后台菜单的 `name` 字段完成页面跳转。

## 为什么这样改

- 这个项目的动态路由本身就是按后端菜单 `path` 组织的。
- `path` 对这类菜单是更稳定、更可控的导航键。
- 改成按 `path` 导航后，即使数据库里的某几个菜单 `name` 配置不规范，也不会影响页面打开。

## 影响范围

- 直接修复本次反馈的以下菜单点击问题：
  - 综合查询 / 维度表
  - 数据报表 / 分行业报表
  - 数据报表 / 企业报表
  - 数据报表 / 企业排名
- 同时也会降低其他动态菜单因 `name` 配置异常导致的静默跳转失败风险。

## 验证建议

- 登录系统后，依次点击上述 4 个菜单，确认地址栏路由切换且页面正常打开。
- 若当前运行的是 `org-tribe-system` 内嵌静态前端，需要重新构建前端或重新打包主系统后再验证。
