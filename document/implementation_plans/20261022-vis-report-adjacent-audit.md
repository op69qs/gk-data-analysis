# 可视化与智能报告相邻功能检查

## 范围与基线

用户在新增方案、月度快报修复后要求“其他也检查下”。本轮修改前已 pull，基线 `c26fa69`；覆盖当前可达的可视化图库、页面、展示方案、预览，以及智能报告的月报、月度快报、季报、季度快报。检查包含预览依赖的指标图查询，没有扩展到指标方案转换、数据对接及其他业务模块。保留原有主服务本地配置，未执行客户现场操作或业务数据库写入。

## 确定问题与修复

| 功能 | 复现的问题 | 处理 |
| --- | --- | --- |
| 图库封面 | 可访问库有 112 条 `p` 图片记录，原类型判断未渲染 | 补充图片封面渲染，沿用已有媒体路径解析 |
| 图库分类与翻页 | 内部布局滚动未触发窗口滚动监听；连续事件可能跳页，旧分类响应覆盖新分类 | 捕获内部容器滚动，过滤无关区域；加载期间锁定下一页，成功才推进页码，失败重试原页，按请求隔离响应；缓存停用及销毁时解绑 |
| 图库编辑 | 保存失败仍关闭；先编辑文本再编辑图片时残留 HTML 可写入图片内容；重复及过期表单校验可写错对象 | 失败保留表单；只对文本提交 HTML；提交和校验使用弹窗代次及忙状态保护 |
| 方案查询与修改/删除 | 异常结果被末尾成功覆盖；跨表修改中途失败可能只完成部分操作 | 正确返回失败，增改删使用事务并回滚，删除前校验 ID，空预览返回固定空数组及计数 |
| 图库接口 | 查询、编辑及批删失败仍报告成功；批删部分失败未整体回滚 | 修正返回状态与事务，拒绝空 ID |
| 方案/图库表单 | 异步校验尚未返回就关闭并打开另一对象，旧值可能提交到新对象 | 在校验前捕获弹窗代次，在回调及提交返回时核对 |
| 历史页面预览 | `COALESCE(NULLIF(...), NULLIF(...), ...)` 未排除空串或字符串 `null`，未回退图库接口 | 使用嵌套 `NULLIF`，保留有效自定义接口路径 |
| 全屏方案预览 | 请求失败或参数缺失时持续遮罩；旧响应及旧子图表回调可提前完成新方案 | 错误/空结果明确显示，提供重试和返回；缺 ID 不请求；隔离响应、子回调与进度定时器 |
| 指标图预览 | 历史 `IndexBarLine/IndexPie` 请求未经过 `/vis/api` 网关，且仅传模块 ID，无法加载图库及模块条件 | 补齐白名单路径前缀，额外传 `gallery_id` 和 `sub_id`，普通查询保持原协议 |
| 图表加载失败 | 请求失败只推进进度，图表仍空白；引用已删除指标方案时空指针 | 显示图表加载错误，区别于正常“暂无数据”；缺失源方案明确提示重新选择图表 |
| 其他报告生成 | 月报、季报、季度快报异常或缺少文字时未正确标记失败 | 统一失败状态处理，缺数据停止生成；成功路径保持原状态契约 |
| 新增报告 | 生成请求发出即关闭；生成中 Modal 的 `change(false)` 可绕过取消回调保护 | 等生成完成再关闭，失败保留输入，同输入重试复用报告 ID；改为受控 `visible` |
| 报告编辑与下载 | 部分模板保存旧 HTML 快照；保存失败仍下载或不提示 | 从当前组件内的编辑 DOM 取内容；失败提示并阻止下载，保留原下载参数协议 |
| 报告 SQL | 聚合后 `::text` 被 Druid 拦截；旧 MySQL 用户变量；月报引用大小写及分组错误 | 仅修语法兼容；保留公式及指标来源，季度图表显式保留原升降序 |

页面管理/编辑的查询分页、保存、发布、删除、同图库多条件契约沿用已有回归，未发现本轮必须修改的其他确定问题。模板管理的 7 张静态模板资源通过生产构建；键盘、滚轮、轮播及媒体路径沿用已有测试。

## 验证证据

- 前端完整测试目录 16 个测试文件通过；新增相邻流程 14 项、方案编辑增至 11 项、报告流程 21 项、请求协议 5 项、图表失败渲染 4 项，均有修复前失败、修复后通过证据。报告 Modal 使用实际 Ant Design Vue 的取消/change 事件序列验证。
- vis 控制器新增 22 项中，修复前 20 项失败、2 项基线通过，修复后全部通过。另补充 2 项指标源方案缺失回归；全模块 JUnitCore `OK (93 tests)`，其中 3 项只读测试默认跳过；显式开启后 3 项全部通过。事务测试使用本地快照存储和 Spring 事务代理，不等同于现场数据库物理回滚验证。
- fixedReport Java 8 打包执行 17 项测试，零失败、错误、跳过。Druid parser/PGWall 共 126 组完整 SQL 通过；当前源码 43 次只读 `EXPLAIN`、4 次原 Mapper 实际 `SELECT` 和 4 次排序夹具通过。图 3/4 保持升序 `[10,20,30]`，图 5/6 保持降序 `[30,20,10]`，行号均为 `[1,2,3]`。
- 数据库检查连接强制只读并回滚，使用配置中可访问的兼容测试库，不是客户现场。其余图表/表格 SQL 主要验证到 `EXPLAIN`，不能据此认定完整文档生成和业务计算结果均已验收。
- 生产构建的真实浏览器联调验证图库内部容器滚动、失败后原页重试、图片封面、图库保存失败保留输入、预览失败退出遮罩和重试。保存失败使用本机拦截响应，未执行数据库保存。
- 实际方案的 4 个指标图请求均经过正确网关并携带图库/模块 ID。只读核对发现这 4 个图库均存在、条件有效，但引用的 4 个源指标方案均已删除。最终浏览器中 4 张图均显示“指标方案不存在或已删除，请重新选择图表”，无页面 JavaScript 异常。这是测试库历史数据缺失，未补造数据，不能据此认定图表实际数据渲染已经通过。浏览器插件连接中断后，最终复核改用本机 Playwright 和现有 Chromium。

## 交付与边界

更新包需同时包含主服务 JAR（内含最终前端）、vis-screen JAR 和 fixedReport JAR。前端独立托管时还需更新静态目录。沿用现场配置、依赖库和部署脚本；交付前核对主服务内全部 57 个前端文件、两个业务 JAR 内修改的 Mapper/类与本次构建一致。

没有实际写入、删除业务数据或执行真实报告文件转换。现场仍需验收方案及图库保存/删除、跨表回滚、真实图表加载、四类报告完整生成、下载文档与内容核对。历史遗留“生成中”记录不自动回填，既有性能限制未扩展优化。
