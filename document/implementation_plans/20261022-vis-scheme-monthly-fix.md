# 现场新增展示方案空白与月度快报生成失败修复

## 现场反馈与同步基线

2026-10-22 收到现场截图：`/vis/bigscreen/schemes` 新增方案弹窗一直显示加载遮罩；月度快报生成分别出现 `src` 别名作用域错误、Druid SQL 解析错误，并有报告长期停留在“生成中”。修改前已 pull，基线为 `2a17482`，包含现场的 `f474234` 月报修复。保留原有主服务本地配置修改。

## 展示方案

新增和编辑共用 `ExhibitionSchemeListModal.edit()`，原逻辑一律开启保存遮罩，但只有存在方案 ID 时才关闭。真实浏览器复现时，78 个页面选项已经加载完成，新增弹窗仍在转圈；问题与数据是否加载成功无关。

现在页面选项的加载状态与保存遮罩分开，表单打开后可输入方案名称。每次打开从第一页查询完整选项后，才按已保存的关系顺序回显；加载失败提供重新加载入口，禁止在数据未加载完整时保存。编辑关系接口严格判断返回状态，关闭后忽略旧请求响应。新增会清空旧方案、旧页面选择及切换间隔。保存失败保留表单，成功后才关闭，避免输入丢失。

真实数据还发现历史方案关联 19 页，其中 1 页已删除。对列表外的关联先按 ID 补查，存在的页补回元数据；确已删除的页保留原关联 ID、缩略图和顺序，并明确提示用户可移除，避免编辑时静默丢失关联。

新增 9 项真实 Vue 组件行为回归，均经过修改前失败、修改后通过验证：新增遮罩、跨分页顺序回显、加载失败重试、关系接口失败、编辑后新增、保存失败保留输入、旧响应隔离、已删除页关联保留、列表外页面按 ID 恢复。测试的表单依赖使用桩，实际 Ant Design 表单交互另由生产构建浏览器检查。

## 月度快报

现场提交 `f474234` 针对第三张表的 `src` 别名作用域问题拍平了嵌套查询，但没有修复第二张表的另一处损坏。`NewsFlashMapper.getTableParams2` 在 `table431` 后混入了第三张表的字段片段，截断 `table432/433/434/441`，Druid 报错位置对应截图中的第 36 行第 168 列 `COALESCE`。截图中的旧 `src` 异常未在本次兼容测试库重现，不能据此推断客户现场的数据库版本行为。

恢复该段指标子查询后，完整 SQL 继续暴露日期函数和聚合投影问题。本轮统一该查询的去年同期日期写法；仅在限定单账期的聚合子查询内用 `MAX(ACCOUNT_PERIOD)` 取得原账期标签，保留原指标来源及计算口径。没有关闭或绕过 Druid Wall 检查。

月度快报生成失败后，将已有报告记录置为 `2=生成失败`，列表补充该状态的显示及筛选。其他报告生成路径未指定状态时，仍沿用原来的 `1=已生成`。该修改不会自动清理历史遗留的“生成中”记录。

## 验证与交付范围

前端按仓库要求使用 Node 14 构建，行为测试使用 Node 22；后端使用 Java 8。数据库检查使用配置中可访问的兼容测试库，连接强制只读并回滚，不是客户现场。Druid PostgreSQL parser 与 PG Wall 检查针对 MyBatis 生成的完整 SQL；真实库检查另行记录执行结果和耗时限制。

两个账期（2026-06、2025-11）的四项查询共 8 次只读 `EXPLAIN` 通过。实际执行本次涉及的原 Mapper：`getTableParams2` 两个账期各返回 1 行、188 字段；`getTableParams3` 分别返回 0 行及 16 行、10 字段。未修改的 `getTableParams` 在一次 15 秒执行限制下超时，定位到 `table163`，未为此扩大本轮修改范围；完整生成链的性能和文档结果没有全部验证。

最终验证结果：

- 前端 12 个测试文件全部通过，其中新增方案行为回归 9 项；fixedReport 模块 Java 8 `clean package` 通过，11 项测试通过，无失败、错误或跳过（含显式开启的只读数据库测试）。
- 生产构建浏览器通过原 Controller、Service、Mapper 查询实际方案与页面，登录壳使用本地测试身份。验证新增表单可输入、78 个页面选项加载、选择两个页面及切换间隔、编辑后新增重置、历史方案 19 项关系完整回显、明确移除已删除页后变为 18 项；无页面 JavaScript 异常。
